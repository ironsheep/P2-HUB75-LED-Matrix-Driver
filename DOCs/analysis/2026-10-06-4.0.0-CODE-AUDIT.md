# 4.0.0 pre-release code audit (2026-10-06)

Read-only audit of every file the 4.0.0 package ships (`release/manifest.txt`: the 14
driver objects, the 11 `demo_hub75_*` files, `isp_hub75_7seg`, `isp_hub75_segment`,
`isp_hub75_anlyCheck`) against the rules of `central:spin2-authoring-guide` that
`tools/check_style.py` does not check (T3 rules excluded). Paths are under `driver/`.
Line numbers are from `afaad02`/`dc2152b`.

**Disposition (Stephen, 2026-10-06): "A please, nothing found outstanding"** — every
finding below is fixed before release, including the demos' dead code. Two behaviour
defects were confirmed by reading before that decision: M1 and M6.

## MUST-FIX

- **M1** rgb3bit.spin2:529-532 (also 309; panel.spin2:221-224, 182; display.spin2:208-214, 186, 196; the `ok` check and `@returns ok ... -1 on failure` in all 11 demos) | 5.1, misleading doc and a functional bug. `startedCog := cog := COGINIT(COGINIT_FREE_COG, @drive_matrix, @ptrCommand) + 1` then `if startedCog == -1`: COGINIT returns -1 on failure (P2KB p2kbSpin2Coginit), the `+ 1` makes it 0, so the failure check never fires and the failure chain above it (panel and display `abort`, each demo's `if ok == -1`) is dead. The doc at 309 says "cogID() of driver cog" but the value is cogID+1. Fix: test the raw COGINIT result for -1 before adding 1, document the +1 convention, and correct the "-1 on failure" docs (these methods abort).
